## Recommended structure

1. **Hook:** the ADSAIPP incident (Step 3) — agent broke a rule that *already existed*
2. **Insight:** "protocol existence ≠ visibility" — the rule was in DSM_0.2 Module C, but spoke agents read the §17.1 alignment template, not the modules (Step 4)
3. **Fix:** the §17.1 template now reinforces what was previously inherited but invisible (F-089, F-087)
4. **Bonus:** sprint boundaries got smarter too (F-090) and session lifecycle got tighter (F-088), both follow the same "operationalize the principle where the agent acts" pattern
5. **Takeaway:** DSM evolves not by adding rules but by relocating them to where they're actually read

## Anti-patterns

- **Do not** list features mechanically. The feature list is in FEATURES.md and CHANGELOG; the blog post's job is the story those sources don't tell.
- **Do not** write a changelog summary. Write the *story behind* the changes.
