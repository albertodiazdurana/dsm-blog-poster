### [2026-06-16] FEATURES update from DSM Central (v1.16.0)

**Type:** Feature timeline notification
**Source:** dsm-central
**Context:** v1.16.0 released 4 new user-facing F-entries (count 136 → 140). Four
collaboration-and-lifecycle protocols from S219, plus EXP-004 audit fixes (not
F-entries). New entries verbatim below for blog coverage consideration.

- **F-140 (2026-06-15) STAA reminder logic with crash-recovery off-by-one fix (BL-442, `/dsm-go` Step 5.7 + `/dsm-staa`)** — The session-start reminder to run STAA on the previous session now cross-references `.claude/last-staa.txt` before firing: it suppresses the reminder when STAA has already analyzed that session or a later one. Previously the reminder fired off the archived transcript's "STAA recommended: yes" text alone, so a session that had already been analyzed still produced a stale prompt. A missing `last-staa.txt` degrades to "remind" (the conservative direction).
- **F-139 (2026-06-15) Open-PR CI status surfaced at boot and wrap-up (BL-441, `/dsm-go` Step 2a.7 + `/dsm-wrap-up`)** — When the current branch has an open GitHub PR, the boot report now surfaces that PR's CI status so a session never resumes on top of silently-failing checks. Failing checks are enumerated, an all-green PR collapses to a one-line summary, and pending checks stay silent. One `gh` call at boot, skipped silently when there is no `gh`, no GitHub remote, or no open PR. Origin: IronCalc S14, where PR #865's `lint-all` was red for 20 days while `/dsm-go` reported "awaiting re-review" from MEMORY.
- **F-138 (2026-06-15) Read-Before-Draft for OSS contributions (BL-437, DSM_0.2.D §9)** — Before drafting a PR or issue body for an external maintained repository, the agent reads the target's contribution surface first: CONTRIBUTING.md, the PR template, the PR-gate workflow files, and one or two recent merged PRs of similar shape. It then drafts against the resulting readiness checklist rather than an internal default, surfacing that checklist in the Pre-Generation Brief Gate 0. Pre-draft hygiene that pairs with Voice-Attribution Review on the same outbound channel.
- **F-137 (2026-06-15) Voice-Attribution Review for byline content (BL-439, DSM_0.2.C §2.3)** — Content posted under the user's byline (PR/issue comments, commit messages, inbox notifications) is the user's words, so approving the send is not the same as approving the content. Network-mediated sends have no diff window the way a file write does, so the agent surfaces the full body in conversation, gets explicit approval of the body, and only then runs the call. A bundling rule keeps a voice-attributed send as its own content gate. Distinct from Cross-Repo Write Safety, which governs the path a write lands on; this governs whose words go out.
